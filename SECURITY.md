# Security Policy

## Поддерживаемые версии

Патчи безопасности применяются к последнему релизу. Старые версии обновляйте перед отчетом.

## Как сообщить об уязвимости

**Не открывайте публичный issue** для уязвимостей безопасности. Используйте **GitHub Private Vulnerability Reporting** (вкладка *Security → Report a vulnerability* на странице репозитория) либо напишите напрямую мейнтейнеру.

Постарайтесь указать:
- версию плагина и EDT;
- описание проблемы и шаги воспроизведения;
- возможное влияние (выполнение кода, утечка данных, отказ в обслуживании);
- предложение фикса, если есть.

Ответ - в течение нескольких дней. Координированное раскрытие приветствуется.

## Модель безопасности

AI-EDT - **локальный** MCP-сервер для рабочего процесса одного разработчика.

- **По умолчанию сервер слушает только loopback** (`127.0.0.1`) без аутентификации. Это подходит для локальной работы AI-клиента и EDT на одной машине.
- **Не публикуйте порт наружу** (в интернет, общую сеть, контейнер с пробросом) без дополнительной аутентификации на уровне reverse-proxy - без нее любой, кто достучится до порта, получит полный доступ к инструментам: чтение/правку метаданных, BSL, запуск отладки, работу с информационной базой.
- **Инструменты могут менять исходники, метаданные и информационные базы.** Используйте **Read-only** пресет для анализа чужого проекта, держите проект в VCS перед правками, отключайте деструктивные операции если они не нужны.
- **`evaluate_expression` и `execute_query`** выполняют BSL в живой сессии 1С - это сознательная возможность для отладки и инспекции, не дефект.

## Что НЕ считается уязвимостью

- Поведение инструментов по назначению (запись BSL, удаление объекта через `delete_metadata_object` с подтверждением, update_database) - это функциональность, а не нарушение безопасности.
- Отсутствие аутентификации на loopback-порту по умолчанию - сознательное решение для локального one-developer сценария. Для сетевого доступа настраивайте аутентификацию внешне.
- Доступ AI-ассистента к данным проекта - это и есть назначение MCP-сервера; ограничивается пресетами и политикой AI-клиента.

## Уязвимости в зависимостях

Зависимости - Eclipse/EDT platform, OSGi runtime, bundled libs (snakeyaml, jsoup, copy-down). Уязвимости в них сообщайте в соответствующие upstream-проекты; мы обновляем bundled libs при выходе патчей.
