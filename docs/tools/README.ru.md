# Каталог инструментов AI-EDT

[← На главную](../../README.md) · [Пресеты](#пресеты-и-видимость) · [Фасады](#ключевые-фасады) · [Обозначения](#обозначения)

Этот каталог показывает поверхность MCP-инструментов AI-EDT по группам из настроек **Window → Preferences → AI-EDT → Tools**. Он отвечает на три вопроса:

1. какой инструмент выбрать для задачи;
2. требуется ли ему запущенная EDT, отладочная сессия или информационная база;
3. может ли вызов изменить проект или данные.

> [!NOTE]
> Текст каталога написан вручную, а вот состав инструментов сверяется автоматически: `scripts/check-tool-catalog.py` сравнивает имена в этом файле с группами `ToolCategory` и роняет сборку при расхождении. Источник истины по JSON-схемам параметров остается за `tools/list` живого сервера.

## Обозначения

| Метка | Значение |
|---|---|
| **Чтение** | Не должен изменять проект или информационную базу. |
| **Изменение** | Записывает исходники, метаданные, настройки или файлы проекта. |
| **Выполнение** | Запускает EDT/1С, тесты, запросы или код в живой сессии. |
| **Опасно** | Может удалить, импортировать, перезаписать или синхронизировать данные. |
| **Смешанный** | Поведение зависит от выбранной операции или параметров вызова. |
| **Фасад** | Единая точка входа для нескольких родственных операций. |
| **Workshop** | Высокоуровневый конструктор сложного артефакта. |

## Аналитика конфигурации

Высокоуровневый анализ структуры и последствий изменений.

| Инструмент | Режим | Назначение |
|---|---|---|
| `dependency_graph` | Чтение | Строит граф зависимостей объектов метаданных. |
| `detect_query_anti_patterns` | Чтение | Ищет производительные и структурные проблемы запросов. |
| `project_metrics` | Чтение | Рассчитывает метрики проекта и состава конфигурации. |
| `compare_configurations` | Чтение | Сравнивает две конфигурации или проекта EDT. |
| `compare_three_way` | Чтение и запись | Сравнивает открытый проект с новой поставкой и с поставкой, от которой обе произошли. По умолчанию читает. Параметр `scope` ограничивает сравнение перечисленными объектами - полное сравнение реальной конфигурации идет минутами и дает дерево порядка двухсот тысяч узлов; нераспознанные имена и то, что среда добавила сама, возвращаются отдельно. Решение можно принять сразу о классе объектов: запись вида `{"select":"matching","rule":"..."}` назначает правило всему, что попало под отбор, и правило каждого объекта перечитывается обратно. При `intent=MERGE` применяет решения к проекту - необратимо; `intent=UPDATE_UNCHANGED` берет поставку целиком без решений и отклоняется, если сравнение не трехстороннее, не завершено или что-то менялось здесь, с обеих сторон либо без атрибуции. Под пресетом без права записи любая запись отклоняется. |
| `impact_analysis` | Чтение | Оценивает последствия изменения или удаления объекта. |
| `support_registry` | Изменение | Читает состояние поддержки поставщика: от каких конфигураций поставщика произошла эта, их релизы, сколько объектов в каждом режиме поддержки, правила, применяемые при следующем обновлении, и режим отдельного объекта вместе с объектами, которые придется менять вместе с ним. Режим - это то, что объявлено, а не то, менялся ли объект; на второй вопрос отвечает `compare_three_way`. `snapshot_modes` записывает карту "объект -> режим" в файл: объединение берет модель поддержки из поставки, и правила объединения этого не отменяют, так что снимок - единственный путь назад. `restore_modes` возвращает записанные режимы и является единственной операцией здесь, которая пишет; без `apply=true` она сообщает, что сделала бы, и не меняет ничего. Операции: `status`, `list_objects`, `object_mode`, `snapshot_modes`, `restore_modes`, `help`. |
| `extension_diff` | Чтение | Сравнивает расширение с основной конфигурацией. |
| `list_interceptors` | Чтение | Показывает перехватчики методов расширения. |
| `find_dead_code` | Чтение | Ищет экспортные методы BSL, которые никто не вызывает и которые не являются обработчиками событий платформы, БСП или перехватчиками расширения. Список кандидатов эвристический - перед удалением проверять вручную. |
| `get_outgoing_structures` | Чтение | Возвращает исходящие структурные ссылки объекта метаданных: типы, владельца, родителя и другие зависимости. |
| [`insights`](#insights) | Фасад · Чтение | Объединяет метрики, графы, сравнение и анализ влияния. |

## Ключевые фасады

Фасады уменьшают размер `tools/list`: вместо набора родственных standalone-инструментов агент видит одну точку входа и выбирает действие через параметр `operation`.

У большинства фасадов встроена справка:

```json
{
  "operation": "help"
}
```

Для подробностей конкретной операции используется `topic`:

```json
{
  "operation": "help",
  "topic": "text_search"
}
```

<a id="code_search"></a>
<details>
<summary><code>code_search</code> - поиск и навигация по коду</summary>

Операции: `text_search`, `object_references`, `method_references`, `resolve_symbol`, `call_hierarchy`, `symbol_info`, `content_assist`, `outgoing_structures`, `help`.

Используйте фасад для исследования BSL и модели перед изменениями. Все операции только читают проект.
</details>

<a id="launch_debugger"></a>
<details>
<summary><code>launch_debugger</code> - полный цикл отладки</summary>

Объединяет запуск/Attach, line и exception breakpoints, `run_to_line`, ожидание suspend, чтение и изменение переменных, stepping, resume, terminate, evaluation и profiling.

Большинство операций требует действующей конфигурации запуска EDT; операции с кадрами требуют приостановленного потока.
</details>

<a id="diagnostics"></a>

## Пресеты и видимость

| Пресет | Что видит и может вызывать агент |
|---|---|
| **Canonical** | Фасады перечислены в `tools/list`; покрываемые ими standalone-инструменты скрыты, но остаются вызываемыми. |
| **All Tools** | Показывает весь зарегистрированный набор. |
| **Read-only** | Отключает запись, отладку, запуск и обновление ИБ. |
| **Editing** | Разрешает чтение и изменение, но отключает группу отладки. |
| **Debug & Test** | Разрешает чтение, запуск, отладку и тесты; отключает изменения и опасные операции. |
| **Code Review** | Оставляет чтение и анализ BSL без записи и запуска. |
| **Custom** | Использует вручную выбранные состояния инструментов. |

Состояния отдельного инструмента:

- **listed** - отображается в `tools/list` и вызывается;
- **callable-hidden** - скрыт из списка, но прямой вызов разрешен;
- **disabled** - вызов отклоняется сервером.
